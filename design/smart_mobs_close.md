# Разумные мобы вблизи (2.10.37)

Разбор того, что было не так с разумными мобами в контакте, что изменено и чем мерил.
Лист кадров — `design/smart_mobs_close.png` (замах, стрелки держат зазор, круг,
выскальзывание).

## 1. Что было

Разумный моб — 1 % обычных врагов (по тактике свой шанс: `smartSpawnChance`), метка
«!», цвет кольца по тактике. Вся «разумность» жила на дистанции:

| тактика | что умела | что делала в упор |
|---|---|---|
| 0 — упреждение выстрела | стреляет с 700 px, ведёт цель по скорости героя | лезла в контакт; в упор стреляла без времени на реакцию |
| 1 — перехват | добавляет упреждение к вектору движения | то же, что обычный моб |
| 2 — увёртка от снаряда | уходит вбок от снаряда за 0.48 с | то же, что обычный моб |

Симуляция на 14 секунд (герой идёт на моба со скоростью 120):

```
тактика      контакт   кольцо 120–190
стрелок      12.48 с   0.4 с
перехватчик  12.48 с   0.4 с
увёртливый   12.48 с   0.4 с
```

То есть все три тактики 77–89 % боя стояли в герое. Отличить «умного» от обычного
можно было только по кольцу и по тому, что он стрелял.

## 2. Что стало

Решатель `smartCloseSteer` в `src/game.h` (состояние — `SmartCloseState` внутри
`Monster`). Работает, пока моб ближе 320 px; дальше поведение прежнее.

| тактика | вблизи |
|---|---|
| стрелок (0) | зазор 168 px с гистерезисом 168/208, отход по диагонали 0.92×; ближе 104 px — не стреляет, выскальзывает вбок 1.5× на 0.32 с, кд 1.1 с |
| перехватчик (1) | на замахе 0.26 с отходит на полшага (0.55×), затем рывок 2.8× на 0.24 с, кд 1.7 с |
| увёртливый (2) | круг ~150 px, смена стороны раз в 1.6 с, нырок к герою 0.8 с раз в 3 с (1.35×) |

Телеграфы (рисуются до удара):

- замах перехватчика — растущая линия удара, мишень на конце и кольцо вокруг тела,
  яркость растёт к концу замаха;
- рывок — плотный след за спиной;
- выскальзывание — пунктир в сторону ухода;
- нырок — двойное кольцо.

## 3. Замеры

```
тактика      логика  игрок  мин  средн  контакт  кольцо  рывки  выск  нырки
стрелок      было     120     1      1   12.48 с    0.4 с     0     0      0
стрелок      стало    120    30     31    0.00 с    1.1 с     0    11      0
стрелок      стало      0   167    188    0.00 с    7.0 с     0     0      0
перехватчик  было     120     1      1   12.48 с    0.4 с     0     0      0
перехватчик  стало    120     1      8   11.55 с    0.4 с     8     0      0
перехватчик  стало      0     1     12    8.98 с    0.5 с     8     0      0
увёртливый   было     120     1      1   12.48 с    0.4 с     0     0      0
увёртливый   стало    120    18     31    0.40 с    0.3 с     0     0      1
увёртливый   стало      0    18     70    0.57 с    2.5 с     0     0      5
```

Читается так:

- **стрелок** больше не входит в контакт никогда: против бегущего героя он
  выскальзывает (11 раз за 14 с), против стоящего держит 167–208 px и 7 секунд
  проводит в окне выстрела;
- **перехватчик** бьёт рывком 8 раз за 14 с вместо того, чтобы давить телом;
  средняя дистанция 8–12 px — это моменты удара, между ними он отходит;
- **увёртливый** держит 18–70 px в среднем и ныряет 5 раз за 14 с: касание
  длится 0,4–0,6 с из 14 вместо 12,5 с — то есть это уже тычок, а не стояние
  в герое.

Стоимость: бой 40 мобов, из них 20 разумных — **7,37 мс/кадр** из 16,7.

## 4. Найденный по ходу баг движения

```cpp
float moveLen = sqrtf(...);
if (moveLen > 1.0f) { m.x += ...; }
```

Тактика отдаёт уже нормализованное направление, и его длина после float-округления
бывала 0.9999999 — враг с «единичным» вектором не двигался вообще. Из-за этого
рывок перехватчика не срабатывал: `speedMul` менялся, а шага не было. Порог снижен
до `0.01`.

## 5. Ограничения

- Дистанция считается до центра героя, без учёта его радиуса: моб «держит 168 px»,
  а не «168 px от края силуэта».
- Стрелок не проверяет, есть ли линия огня: за стеной он всё равно выстрелит.
  Стен на арене мало, но это остаётся.
- Перехватчик не умеет отменять замах, если герой ушёл: рывок идёт по линии,
  запомненной в начале замаха (это и делает его читаемым).
