# CHANGELOG — ShadowSurvivors 2.10.7+

## 2.10.7 (текущая версия) — «Скачанный с GitHub update.bat больше не падает»

### Что случилось
Скачанный с GitHub `update.bat` закрывался сразу после запуска. Код был ни при чём:
в репозитории стоял атрибут `*.bat text eol=crlf`, то есть CRLF делался **только при
выгрузке через git**. Кнопка **Raw** и скачивание ZIP отдают содержимое репозитория
как есть — с LF. `cmd.exe` на файле без CRLF падает при разборе первого же
многострочного блока, поэтому окно исчезало мгновенно.

Проверка блоба до правки: `CRLF 0, одиночных LF 151`.

### Что сделано
- `update.bat` хранится **как есть, с CRLF внутри** (`-text -eol` в `.gitattributes`):
  Raw, ZIP и `git checkout` теперь дают одинаковые байты.
- Проверено кругом: коммит → клон с `core.autocrlf=true` → `CRLF 151 из 151`,
  одиночных LF нет.
- Остальные батники остались текстовыми, чтобы diff читался; правило про Raw
  записано в `.gitattributes` рядом с атрибутами.
- Плата за это одна: diff по `update.bat` теперь показывается как «binary» —
  `git diff --text update.bat` по-прежнему печатает построчно.

### Если файл уже скачан
Старую копию можно починить одной строкой в PowerShell (в папке игры):

```powershell
$p="$PWD\update.bat"; $t=[IO.File]::ReadAllText($p)
[IO.File]::WriteAllText($p, ($t -replace "`r?`n","`r`n"), (New-Object Text.UTF8Encoding $false))
```

Проще — скачать файл заново после этой версии или взять его через
`git checkout origin/main -- update.bat`.

## 2.10.6 — «update.bat обновляет main, а не рабочую ветку»

### Почему батник сломался после смены веток
`update.bat` делал `git pull` **той ветки, которая открыта**, а готовая игра всегда
собирается из `main`. Пока работа шла в `main`, это совпадало. С ветками `arena/...`
совпадение кончилось, и поломок стало две:

| Что происходит | Что видел игрок |
|---|---|
| ветка жива, `main` ушёл вперёд | «Already up to date», затем сборка **старой** версии |
| ветку удалили на GitHub после merge | `fatal: … no such ref was fetched`, скрипт падал до сборки |

Оба сценария воспроизведены на копии репозитория с локальным origin — не на догадке.

### Что делает скрипт теперь
1. `git fetch --all --prune`.
2. Печатает **версию и коммит, которые реально лежат на GitHub в `main`** — именно это
   число сравнивают с версией из чата.
3. Если открыта не `main`, переключается на неё (`git switch main`). Ничего не
   удаляется: правки уезжают в прежнюю ветку, а в конце скрипт пишет, как вернуться.
4. Привязывает upstream, если у локальной `main` его нет.
5. `git pull --ff-only` — и только потом сборка.

### Ошибки теперь объясняются
- нет git / папка не git-копия → команда `git clone`;
- нет сети или нет ветки `main` на GitHub → что именно проверить;
- незакоммиченные правки мешают переключению → `git status`, `git stash -u`,
  `git switch -c main --track origin/main`, `git stash pop`;
- `main` разошлась с `origin/main` → печатается число своих коммитов поверх
  `origin/main`, дальше `git log --oneline origin/main..HEAD`;
- обновлений нет, и версия совпала с GitHub → «это последняя версия», а если не
  совпала — «файлы разошлись с репозиторием» и `git diff origin/main --stat`.

- Консоль переключается в UTF-8 (`chcp 65001`), поэтому русский текст скрипта больше
  не читается как мусор.

## 2.10.5 — «Реплика громче боя: своя шина и приоритет»

### Почему «тихо» было не в записях
Все семь фраз — `breakthrough`, `player_death`, `portal_found`, `portal_used`,
`story_act4`, `story_case_closed`, `voice_on` — лежат в банке ровно так же, как
остальные: 16 кГц моно, rms 4,9–5,2 тыс., речь −14…−15 дБ, пик-фактор 3,9–4,3.
`check_voice.py --levels --voice` к ним претензий не имеет, и «сделать файл громче»
здесь было бы лечением не той болезни.

Замер микшера показал настоящую причину: реплика входила в общую сумму с усилением
**1,20**, каждый эффект — с **1,75**, и вся сумма проходила через мягкий лимитер
с коленом 0,62. На прорыве (музыка орды плюс десятки эффектов) сумма уходила за
колено, и лимитер прижимал голос вместе с боем. Формально равная громкость файла —
и тише всего вокруг в игре.

### Что сделано
- **У рассказчика своя шина:** `VOICE_BUS_GAIN = 1,45` (+1,6 дБ к прежнему 1,20).
  Эффекты и музыка остались на своих усилениях.
- **Присед под фразу:** эффекты `×0,58` (−4,7 дБ), музыка `×0,34` (было 0,60 под
  репликой). Атака приседа 14 мс, возврат около 100 мс — без провалов и «качелей».
- **Лимитер видит только программную шину** (музыка + эффекты). Реплика смешивается
  после него и получает собственный ограничитель на 0,94: плотный бой её больше не
  подсаживает, а пик остаётся ниже нуля.
- Если реплика молчит, микс совпадает с прежним **до сэмпла** — проверено рендером,
  `max |diff| = 0,0`. Бой, музыка и эффекты не изменились.
- **F3:** строка `ГОЛОС ШИНА` — усиление шины и живой присед эффектов в дБ. Раньше
  панель показывала, сколько фраз записано, но не то, насколько громко они звучат
  в бою.

### Замер (офлайн-рендер того же боя: 5 с, музыка орды, реплика «Прорыв. Держись.»)

| | было | стало |
|---|---|---|
| голос над боем | +13,9 дБ | **+15,5 дБ** |
| музыка под фразой | ×0,60 | ×0,34 (−5,3 дБ) |
| эффекты под фразой | ×1,00 | ×0,58 (−4,7 дБ) |
| проход через лимитер | голос вместе с боем | голос поверх, ограничитель 0,94 |
| пик в плотном бою | −6,4 дБFS | −5,4 дБFS, клипов 0 |

Файлы не перезаписывались: причина была в шине, а не в голосе.

## 2.10.4 — «Сорок разных цветов и живые стражи»

### Иконки предметов
- Цвет шёл по кругу из десяти оттенков: предметы 00, 10, 20 и 30 носили один тон,
  и в слоте их нельзя было различить. Теперь **у каждого из сорока предметов свой
  цвет**: семейство задаёт смысл (огонь — оранжевый, кровь — красный, лёд — бирюза,
  ветер — зелёный, руны — фиолет, магнит — пурпур, пергамент — янтарь, бездна —
  тёмный фиолет), вариант внутри семейства — вес предмета (тяжёлая печать темнее).
- Минимальное расстояние между тонами выросло с 12 до 30 единиц RGB: пары вроде
  «предмет 19 и предмет 32» больше не сливаются.
- Подложка: у оружия — квадратная стальная пластина, у артефакта — круглая
  каменная шайба. Форма видна раньше цвета, поэтому оружие и артефакт больше не
  путаются в слоте.
- Источник цвета теперь один: `tools/generate_icon_color_atlas.py` строит и атлас
  иконок, и таблицу `ITEM_TONE` в `src/renderer.h` — рамка слота и иконка всегда
  одного тона.

### Стражи
- **Азарот.** Каждый удар сердца выходит кольцом, в ярости вихрь пепла ускоряется
  в 1,6 раза — фигура не просто стоит, а живёт.
- **Протоколист.** Раз в 2,6 с переворачивается страница тома, по скрижали-лицу
  идёт сканирующая строка, перо пишет по дуге.
- **Двойник.** У настоящего тела появился шлейф из двух запоздавших слепков —
  видно, кто из двух тел отстаёт.

## 2.10.3 — «Обновление снова доходит до компьютера» — «Обновление снова доходит до компьютера»

### Почему «версия 2.9.99, а по факту 2.9.83»
Работа шла в ветке `arena/0b44fe48-shadow-survivors`, а `main` оставался на коммите
`0fa8867` — том, с которого ветка начиналась. `update.bat` делает `git pull` текущей
ветки, то есть на `main` не приходило ничего: локальная копия честно отвечала
«Already up to date», и собиралась старая игра.

- Вся ветка (2.9.83 → 2.10.3, 134 файла) влита в `main`. `git pull` теперь приносит
  и кампанию, и ветки, и стражей, и звук.
- `update.bat` печатает **ветку, коммит и версию до и после pull** и отдельно
  предупреждает, если обновлений не было: «Ветка main уже на коммите …, версия …».
- `build_windows.bat` после успешной сборки перезаписывает `ShadowSurvivors.exe`
  в корне. Раньше рядом лежали `ShadowSurvivors_2.9.70.exe` и старый
  `ShadowSurvivors.exe`, и запускался именно старый — при свежей сборке в папке.

## 2.10.2 — «Голос слышен: плотность вместо уровня» — «Голос слышен: плотность вместо уровня»

### Почему реплики были тихими
Жалоба «слишком тихо» не лечилась громкостью, потому что дело было не в ней.
Замер: у свежих фраз RMS совпадал с банком (3750 против 3767), но **пик-фактор**
был 7,1–7,5 против 4,7 у старых записей. Фраза с высоким пик-фактором почти всё
время звучит тихо, а «громкость» набирает на одном щелчке — на слух она тише
соседей при формально равном RMS.

### Что сделано
- В `normalize_voice.py` появился режим `--dense`: он приводит не только RMS,
  но и пик-фактор к коридору банка. Параметры подобраны по замерам: цель 0,160 RMS
  при потолке 0,70 даёт crest ≈ 4,7 и `rms 4851–5242`.
- Весь банк (67 записей) пересобран этим режимом. Это ровно то, что просили:
  фразы больше не выпадают из общего уровня, и в целом банк стал на 2,4 дБ громче.
- `check_voice.py --levels` теперь проверяет и плотность: коридор RMS 4650–5400
  плюс пик-фактор 3,3–5,4. Клип «в норме по RMS, но пустой» больше не пройдёт.
- Перезаписаны своим голосом: `player_death`, `portal_found`, `portal_used`,
  `resonator_spawn`, `story_act4`, `story_case_closed`, `voice_on`, `breakthrough`.
  Чужим голосом в банке осталось 2 клипа.
- Бриф последнего боя записан **одним проходом** — склейка из трёх кусков давала
  неверную интонацию на «Контур разорван» и «Последний бой не вернёт погибших».
- Реплика способности стража: «Уходи из зоны удара!» → «Зона удара! Уходи!»
  (короткий приказ вместо ровного предупреждения).

## 2.10.0 — «Промпты музыки по делам, финальный брифинг» — «Промпты музыки по делам, финальный брифинг»

### Музыка: промпт на каждый бой
- В `music_prompts.md` добавлены промпты **под каждое из 28 дел**, под шесть стражей
  и их усиленные «возвращения», под эндлес-набор и под служебные экраны.
- У каждого дела свой темп (96–152 BPM), свой тембр из истории и обязательная
  боевая подложка: пульс на каждую долю, никакого вокала, первые 8 секунд уже
  в бою, петля в конце.
- Финальный брифинг переписан: «Контур **разорван**, но ночь ещё держится.
  Последний бой не вернёт погибших. Он **оставит** живым право помнить самим».
  Причина — слово «разомкнут» это омограф (`разОмкнут` / `разомкнУт`), и синтез
  читал его как будущее время; попутно убрано повторение «вернёт … вернёт».

  в 260 мс ставит сборка. Короткий кусок не оставляет синтезу простора угадывать
  ударение по всему абзацу.
- `check_voice.py` теперь ловит слова-омографы до записи, а не после: «разомкнут»,
  «замок», «черти», «духи», «мука», «выкупить».
- Имя трека и номер дела сошлись один-к-одному: `ss_gameplay_case07.mp3` играет
  седьмое дело (раньше выбор был сдвинут на единицу).
- Перезаписаны своим голосом: `mission_brief_26`, `boss_ability`, `boss_phase`,
  `boss_summon`, `breakthrough`, `breakthrough_warning`, `build_tier_up`,
  `campaign_end`. Другим голосом в банке осталось 9 клипов вместо 15.

## 2.9.98 — «Ветки, новая ночь, финал, читы, боссы, музыка» — «Ветки, новая ночь, финал, читы, боссы, музыка»

Большой проход по списку замечаний: одиннадцать правок в геймплее, интерфейсе и звуке.

### Ветки кампании
- Развилки были обязательными: чтобы пройти дальше, требовалось закрыть **обе** ветки.
  Теперь это выбор — пройдя одну, вторую не взять.
- Причина была в пререквизитах: `prereqA` и `prereqB` проверялись как «И». Теперь «ИЛИ»,
  а вторая ветка пары блокируется, как только первая закрыта.
- В списке дел пара рисуется развилкой: обе карточки сдвинуты вправо, в жёлобе стоит
  вилка, на карточках метки **А** и **Б**. В портретной раскладке — то же самое.

### «Новая ночь» и золото
- После финала появилась кнопка **НОВАЯ НОЧЬ**: дела открываются заново, можно выбрать
  другой след, а золото в делах кампании умножается: ×2 после первого ресета, ×3 и ×4

### Крысы

  Теперь — кучка радиусом ~54 px с общим направлением.
- Крыса, убежавшая от героя дальше 0,9 от длинной стороны экрана, убирается сразу,
  а не доживает таймер за краем экрана.

- Фраза читается **при открытии выбора дела** (описание того дела, на котором стоит
  курсор) и **при старте самого дела**. Раньше описание было только текстом, а из

- Записанные фразы длятся 8–14 секунд, поэтому строка «цель обновлена» теперь ждёт
  окончания описания, а не перебивает его на первом слове. Общая фраза в этом случае

- Записаны дела 01–10; остальные пока читает общая фраза. Проверка:
  `python3 tools/check_voice.py` → строка «описания дел: N из 28».

## 2.9.83 — «Версия, кампания, стражи»

### Версия больше не разъезжается
- **Причина была в сборочном скрипте.** `build_windows.bat` сначала читал локальный
  `version.txt` и только потом `src/version.h`, поэтому у вас собирался 2.9.78, хотя

- Добавлен `python3 tools/check_version.py --strict`: сверяет `GAME_VERSION`,
  `GAME_VERSION_NUM`, последнюю запись хроники и заголовок CHANGELOG. Расхождение
  теперь видно до сборки.

### Кампания открывается на актуальном деле
- Выбор ложится на **последнее доступное дело**, а не на первое: вернулись в меню —
  сразу стоите на том, что дальше. Когда все доступные дела закрыты, курсор на
  последнем; заодно сразу открывается нужный акт.

### У каждого стража своя тактика
- **Моргар** — стена: залп тяжёлых болтов, ударная волна вокруг себя, зовёт
  щитоносцев. Единственный, кто закрывается щитом.
- **Малакор** — зоны: самонаводящиеся сгустки чумы и лужа под игроком, зовёт
  заражённых слизней.
- **Кардинал** — линия: узкий быстрый веер и рывок по прямой, ставит писарей-стрелков.
- **Азарот** — кольцо: спираль искр и кольцо с проходом (телеграф заранее показывает
  разрыв), поднимает двух тяжёлых стражей. Раньше его «огненное кольцо» было той же
  волной, что у Моргара, только больше — общий приём убран.

## 2.9.82 — «Каждое дело — своё место»

### Пять арен вместо одной
- **Руины, Крипта, Собор, Пепельный трон и Сердце Архива** — разные места, а не один
  пол с другой подсветкой: своя кладка и швы, своя палитра, свой огонь у жаровен, свои
  ориентиры (обрушенная арка, курган костей, витражная колонна, обугленный обелиск,
  стопки фолиантов), свой мусор под ногами и свой воздух — пыль, оседающий пепел,
  поднимающиеся искры, летящие страницы.
- В кампании место задаёт акт дела, в Endless они сменяют друг друга по ходу ночи.

### Бои перестали быть копиями
- **Гарнизон у каждого места свой.** Крипта выставляет щитоносцев и тяжеловесов, собор —
  стрелков, пепельный трон — броню и элиту. Плюс место задаёт стартовый уровень
  гарнизона: архив не открывается импсами.
- **Отряды вместо россыпи.** Раз в 17–26 секунд с одного края приходит линия из 3–5
  бойцов одного типа (в поздних актах — клещи со второго края). Читается как «идут»,
  а не «что-то появилось».
- **Своя походка у каждой семьи:** имп дёргается, скелет марширует, слизь прыгает и
  сжимается, призрак висит над полом, огр топает. Сжатие/растяжение добавляет
  недостающий кадр анимации без нового арта.
- **Своя смерть:** кости, слизь, искры, пепел, страницы — по материалу семьи.
- **Свой знак у каждого стража:** решётка ворот, разбитая колба, разлинованный реестр,
  зубчатое колесо архива.

## 2.9.78 (текущая версия) — тихая охота отделена от прорыва

Раньше «тихая охота» и «прорыв» были одним и тем же: «внезапно больше врагов».
Теперь это два разных инструмента — возможность и стена.

### Тихая охота = возможность
- Приходит **конечная стая из 20 зверей**, которые идут по следу. На экране счётчик:
  «ТИХАЯ ОХОТА: ОСТАЛОСЬ 12 ИЗ 20 • 18 с».
- Монеты больше **не выдаются заранее**: стая роняет их по мере гибели (каждая третья
  тварь), а за добитую стаю платят награду золотом.
- 30 секунд на всё. Не успел — стая уходит, и ты теряешь **только награду**:
  ни смерти, ни штрафа, прогресс не блокируется.
- Не запускается во время прорыва: две системы больше не накладываются.

### Прорыв = стена
- Без изменений по механике (18 секунд натиска, надо получить удар, потом передышка),
  но теперь он единственный, кто наказывает за бездействие, — и в словаре это
  сказано прямо: «обойти нельзя — в отличие от тихой охоты».

### Озвучка
- «Страж приближается» был тише остальных (пик уже в потолке, тело фразы мягкое).
  Добавлен мягкий лимитер только для этого клипа: RMS 0.098 → 0.175, пик 0.88,
  без клиппинга и без перезаписи.
- Записаны ещё 8 фраз: boss_ability, boss_summon, portal_found, resonator_spawn,
  resonator_destroyed, phoenix_revive, build_tier_up, voice_on.
- Итого 34 из 36. Осталось два: `portal_used` (синтезатор вернул тишину —
  нужен новый дубль) и `breakthrough_pressure` (фразу заблокировала модерация,
  нужна другая формулировка).


## 2.9.77 (текущая версия) — словарь терминов и чистый выход босса

### Понятность

  остаётся голос по умолчанию, при отсутствии движка — тишина без ошибок.
  Громкость озвучки следует за ползунком «Уровень эффектов».
- **Переключатель.** В настройках появился пункт «Озвучка сообщений в бою» (клавиша `8`).
  Пункт «Музыка» удалён: музыка теперь только из `audio/`, варианты больше не нужны.
- **Реестр сообщений.** Каждое сообщение описано в `src/messages.h` с ключом и
  пометкой «озвучивать / молчать»; попапы урона и матрёшек озвучивать нельзя —
  иначе голос захлёбывается. Оверлей `F3` показывает, сколько видов сообщений
  реально использовано и сколько строк реестра битые (должно быть 0).

### Отладка
- **F3 — техническая панель** в левом верхнем углу: версия и номер сборки, состояние,

## 2.9.71 (текущая версия) — сборка без расхождений

### Сборка
- **Одна версия на всё.** `build_windows.bat` передаёт версию компилятору
  (`-DGAME_VERSION="x.y.z" -DGAME_VERSION_NUM=xyzz`, см. `src/version.h`), и она же
  попадает в имя `.exe`, в свойства файла (`resource.rc` генерируется из того же значения),
  в заголовок окна и в «Хронику обновлений». Раньше заголовок окна был зашит на `2.9.53`,
  а хроника — на `2.9.70`, при том что собиралась версия `2.9.70`.
- **`build_windows.bat` работает как обещано:** `build_windows.bat 2.9.71` собирает
  именно `2.9.71` (аргумент раньше игнорировался).
- **CRLF в `build_windows.bat`.** Файл лежал в репозитории с LF-переводами строк —
  `cmd.exe` на этом ломает многострочные блоки. Добавлен `.gitattributes`
  (`*.bat text eol=crlf`), так что кодировка концов строк больше не зависит от
  `core.autocrlf` на машине сборки.
- **Пустой `version.txt` больше не ломает нумерацию.** Файл `version.txt` был пустым,
  поэтому каждая сборка снова собирала `2.9.70` и затирала предыдущий `.exe`.
  Теперь: аргумент → `version.txt` → резервное значение, лишние пробелы/CR обрезаются,
  формат `x.y.z` проверяется, а после успешной сборки в `version.txt` пишется следующая версия.
- **Сборка не уничтожает рабочий билд.** Компиляция идёт в `build/`, готовый `.exe`
  копируется на место только после успеха, поэтому упавшая сборка не оставляет
  проект без запускаемого файла.
- **`build/` — каталог для артефактов.** `resource.rc`, `resource.o` и `build.log`
  больше не пишутся в `src/` и не попадают в Git; добавлен `.gitignore`,
  из индекса убраны `src/resource.rc`, `src/resource.o`, `build.log`, `crash.log`.
- Пути считаются от каталога скрипта, поэтому `build_windows.bat` можно запускать
  из любого рабочего каталога.

### Исправления
- Переполнение буфера в обработчике падений: `char buf[16]` под 64-битный `%p`
  (`0x` + 16 hex + NUL) — теперь `buf[32]`.
- `crash.log` больше не создаётся при каждом запуске: файл пишется только при
  реальном падении.
- Советник по улучшению «Печать разоблачения» писал обрезанную (битую UTF-8)
  подсказку из-за `snprintf` в буфер 112 байт — теперь 160.
- Убраны магические числа в «Хронике обновлений»: `PATCH_NOTES_COUNT` вместо `67`/`68`,
  `PATCH_NOTES_VERSION` берётся из версии сборки, добавлена страница `2.9.71`.
