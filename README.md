# Shadow Survivors — «Пепел Тьмы»

Выживание против орды: автоматическое оружие, прокачка во время боя, четыре
печати кампании и забеги без конца. Игра целиком на C++ в заголовочных файлах,
без движка и без сторонних библиотек: одна папка `src/`, две платформы —
Windows (`.exe`) и Android (`.apk`).

---

## Что нужно, чтобы запустить

### Windows (основная версия)

| что | зачем |
|---|---|
| Windows 10/11, 64-бит | игра — программа win32 (`main_win32.cpp`) |
| [MSYS2](https://www.msys2.org/) или [winlibs](https://winlibs.com/) с **MinGW-w64 g++ 12+** | компилятор и `windres` (иконка и версия в exe) |
| больше ничего | графика, звук и шрифты — свои, лежат в `src/` |

Установка компилятора в MSYS2 (один раз):

```
pacman -S mingw-w64-x86_64-gcc
```

и добавьте `C:\msys64\mingw64\bin` в `PATH`.

### Android

| что | зачем |
|---|---|
| JDK 17+ | Android Gradle Plugin 8.x |
| Android SDK (platform-tools, platforms;android-34, build-tools 34) | сборка APK |
| NDK 26.1.10909125 и CMake 3.22.1 | ими собирается `src/main_android.cpp` |

Подробно, с командами `sdkmanager` и разбором ошибок — [`ANDROID_BUILD.md`](ANDROID_BUILD.md).

### Linux / macOS

Собрать саму игру нельзя (win32 API), но **все стенды и проверки работают** —
именно на них проверялась эта версия. Нужен `g++` с C++17 и `python3`.

## Собрать и запустить

### Windows

```
build_windows.bat
```

Двойной щелчок делает всё: берёт версию из `src/version.h`, собирает иконку
через `windres`, компилирует и кладёт готовый файл в `build\`:

```
build\ShadowSurvivors.exe
```

Журнал сборки — `build\build.log`. Если что-то не так, батник покажет хвост
журнала и не закроется.

Запуск с ключами (необязательно):

```
build\ShadowSurvivors.exe --graphics 3 --threads 4
```

- `--graphics 0..4` — АВТО / ВЫСОКОЕ / СРЕДНЕЕ / БЫСТРОЕ / ЭКОНОМ (то же есть в
  настройках, клавиша `0`);
- `--threads 1..8` — сколько потоков рисуют кадр полосами (`0` — по числу ядер).

### Android

```
build_android.bat            :: debug-APK  -> build\ShadowSurvivors_<версия>_debug.apk
build_android.bat install    :: собрать и сразу поставить на телефон
```

Батник сам находит Java, SDK и Gradle. Что делать, если не собралось —
[`ANDROID_BUILD.md`](ANDROID_BUILD.md), раздел «Если не собралось».

## Управление

**Клавиатура и мышь (Windows):**

| | |
|---|---|
| `WASD` / стрелки | движение |
| мышь | прицел, левая кнопка — огонь/выбор |
| `Пробел` | рывок |
| `Q` | суперумение |
| `Esc` | пауза, выход из подменю |
| `F3` | техническая панель: ступень графики, цена кадра, потоки |
| `F9` (или `` ` ``) | отладка: герой, ресурсы, телепорт, спавн |

**Android (APK):** при первом запуске игра сама предлагает три схемы движения —
`СТИК СЛЕВА`, `СТИК СПРАВА` (для левшей) и `КРЕСТОВИНА`. Каждая карточка рисует
схему так же, как она выглядит в бою; выбранная запоминается в настройках, а
сменить её можно кнопкой `УПРАВЛЕНИЕ` на экране настроек.

| схема | движение | кнопки |
|---|---|---|
| стик слева | левая нижняя часть экрана, центр — там, где коснулись | справа: `СУПЕР`, `РЫВОК` |
| стик справа | то же зеркально, правой рукой | слева |
| крестовина | четыре кнопки-стрелки, диагональ — двумя пальцами | справа |

Палец справа (вне кнопок) — прицел и огонь, `II` — пауза, `ОТЛ` — техническая
панель. Списки (справка, патчноуты, выбор дела) листаются пальцем. Названий
клавиш на телефоне нет: `WASD`/`Пробел`/`Q` заменены на подписи кнопок, а
подсказки вида `[ESC]` убираются. Схемы нарисованы на листе
[`design/touch_controls.png`](design/touch_controls.png).

**Размер кнопок** — настройка, а не константа: «Размер кнопок касания» в
настройках (или ползунок «− / +» на экране «УПРАВЛЕНИЕ»), ступени 80, 90, 100,
110, 125, 140, 160 %. Один процент масштабирует кнопки `СУПЕР`/`РЫВОК`,
крестовину, стик и служебные кнопки. Если кадр узкий (окно в сплите), размер
ужимается по экрану, чтобы кнопки не вылезли за край. Как это выглядит при
80 / 100 / 160 % — лист [`design/touch_sizes.png`](design/touch_sizes.png).

**Внешний вид кнопок** — отдельный экран «ВНЕШНИЙ ВИД КНОПОК» (с «УПРАВЛЕНИЯ»
или клавишей `L`): стиль (`СТЕКЛО` / `ПЛОТНЫЕ` / `КОНТУР` / `КРУГ`), цвет
(`ЯНТАРЬ` / `НЕОН` / `МОНО` / `УГЛИ`), прозрачность (40…100 %) и размер.
Превью на экране рисуется тем же кодом, что бой, и рядом показано «ОБЫЧНО /
НАЖАТО». Кнопка «СБРОСИТЬ ВНЕШНИЙ ВИД» возвращает прежний вид, размер при этом
остаётся. Листы: [`design/touch_styles.png`](design/touch_styles.png),
[`design/touch_themes.png`](design/touch_themes.png),
[`design/touch_look.png`](design/touch_look.png).

**Предметы — 41.** Сорок первый, «Тлеющая Тропа» (тир IV), работает не от
удара, а от шага: герой оставляет на полу тлеющие метки, и всё, что стоит на
них, горит (6/9/12 урона раз в 0,55/0,50/0,45 с, метка живёт 2,6 с, хвост до
14 меток). Стоя на месте след не появляется. Разбор, числа и снимки —
[`design/item_41_trail.md`](design/item_41_trail.md),
[`design/ash_trail.png`](design/ash_trail.png),
[`design/icon_sheet_41.png`](design/icon_sheet_41.png). Иконка у предмета одна,
а рисунков — три, по одному на каждый стиль (`ВЕКТОР`, `ИИ-АРТ`, `ЦВЕТ`):
[`design/icon_40_styles.png`](design/icon_40_styles.png).

## Где лежат файлы игры

**Windows** — рядом с `ShadowSurvivors.exe`:

```
shadow_survivors.sav     прогресс, рекорды, открытые герои
shadow_survivors.cfg     настройки (громкость, графика, переключатели)
audio/                   своя музыка и озвучка (mp3); нет файлов — играет встроенная тема
```

**Android** — во внутреннем каталоге приложения (там же, где `audio/` и
`crash.log`; путь виден в `adb shell run-as com.shadowsurvivors.game ls files`).
Сейв переживает обновление APK, но удаляется вместе с приложением.

## Проверки и стенды

Всё, что можно проверить без телефона и без второго компьютера. Стенды
собираются обычным `g++` и на Windows, и на Linux.

```
g++ -O2 -std=c++17 -pthread -Isrc tools/screen_check.cpp -o build/screens
build\screens 2 1
```

| стенд | что отвечает |
|---|---|
| `tools/screen_check.cpp` | хеши одиннадцати экранов: кадр изменился или нет (и одинаков ли он в 1, 2, 4 потока) |
| `tools/screen_shot.cpp` | один экран в BMP — когда хеша мало и надо посмотреть глазами; аргумент `touch` включает телефонный интерфейс, экран `trail` — бой с тлеющей тропой, `icons0/1/2` — стиль иконок, `scrollN` — прокрутка арсенала |
| `tools/perf_bench.cpp` | цена кадра в мс; код 1, если не влезает в 16.7 мс. Аргумент `trail` — сцена с тлеющей тропой (предмет 40): герой бежит по кругу и оставляет след |
| `tools/touch_probe.cpp` | 166 проверок касаний против настоящей игры: три схемы, крестовина и диагональ, зеркало, мёртвая зона, размер и внешний вид кнопок, прокрутка пальцем, чтение старых файлов настроек, три минуты забега без падений |
| `tools/android_smoke.cpp` | 48 проверок: исполняет **весь Android-слой** на поддельном NDK — поток игры, EGL, AAudio, ассеты, пауза/возврат, первый запуск с выбором схемы, размер и внешний вид кнопок из настроек, запись в файл, сейв при выходе |
| `tools/trail_probe.cpp` | 43 проверки предмета 40: след не появляется стоя, шаг и длина хвоста, время жизни метки, такт и кратность урона, ранги, резонатор и страж, уборка следа вне боя, отрисовка |
| `tools/touch_preview.cpp` | рисует схемы управления на кадре боя (`design/touch_controls.png`), размеры (`sizes` → `design/touch_sizes.png`), стили (`styles` → `design/touch_styles.png`) и цвета (`themes` → `design/touch_themes.png`) |
| `tools/bake_ai_icon.py` / `tools/generate_icon_color_atlas.py` | иконка предмета в оба атласа: первый вшивает один предмет, второй пересобирает стиль «ЦВЕТ» целиком |
| `python3 tools/make_icon_sheet.py` | лист всех иконок из того же атласа, что идёт в exe (`design/icon_sheet_41.png`) |
| `tools/style_preview.cpp` | три стиля иконок одного предмета рядом, в трёх размерах слотов (`design/icon_40_styles.png`); рисует та же функция, что игра, и возвращает код 1, если в каком-то стиле слот пустой |
| `python3 tools/check_version.py --strict` | номер версии не разъехался между `version.h`, хроникой и CHANGELOG |
| `python3 tools/check_android_bat.py --strict` | батник, gradle, CMake, манифест, иконки и то, что инструкция не врёт про файлы |

Одной командой Android-часть (включая оба исполняющих стенда):

```
bash tools/check_android.sh
```

## Честно о том, что проверено

- **Windows-версия** собирается `build_windows.bat`; `.exe` в репозитории не
  лежит — он собирается у вас (бинарники в git не хранятся).
- **Android-версия** собирается `build_android.bat`. APK в репозитории тоже нет:
  нужен NDK. Сам батник проверен статически, а Android-слой — исполняющим
  стендом на поддельном NDK (см. `design/android_check.md`), но **на живом
  телефоне он ещё не запускался**: первый запуск — ваш.
- Все стенды и проверки выше проходят на этой версии; что именно прогнано —
  в [`design/android_check.md`](design/android_check.md).
